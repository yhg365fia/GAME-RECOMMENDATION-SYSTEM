# 오늘 진행한 내용

## 1. 추천 시스템 평가 방식 설계

기존에는 전체 데이터를 이용하여 추천을 수행하였다.

하지만 실제 추천 시스템에서는
모델을 학습한 데이터와 평가하는 데이터가 분리되어야 한다는 점을 깨달았다.

이를 위해 추천 시스템 전용 평가 데이터셋을 구축하기 시작하였다.

학습 데이터
- Train

평가 데이터
- Test

향후 Precision@K, Recall@K, MAP, NDCG 등을 계산할 수 있도록 구조를 변경하였다.

---

## 2. 평가 대상 사용자 선정

리뷰가 너무 적은 사용자와
비정상적으로 많은 리뷰를 가진 사용자는 제외하였다.

```python
lower_bound = 10
upper_bound = 78
```

조건

- 최소 리뷰 수 : 10개
- 최대 리뷰 수 : 78개

선정된 평가 대상

```
647,035명
```

---

## 3. 사용자 단위 Train/Test 분할

처음에는

```
전체 데이터를
70 : 30
```

으로 단순 분할하려고 하였다.

그러나 추천 시스템은

> "사용자"

가 가장 중요한 단위라는 점을 고려하여

사용자별 리뷰를

```
Train 70%
Test 30%
```

으로 분리하였다.

즉,

```
User A

게임1
게임2
게임3
게임4
게임5
```

↓

```
Train

게임1
게임2
게임5

Test

게임3
게임4
```

처럼 분할하였다.

---

## 4. 사용자 단위 샘플링 구현

기존

```
train_test_split()
```

방식을 사용하였지만

64만 명 이상의 사용자 그룹을 반복 처리하면서
속도가 매우 느려지는 문제가 발생하였다.

이를 해결하기 위해

```
groupby().sample()
```

방식으로 변경하였다.

```python
test_df = (
    eval_df
    .groupby("user_id", group_keys=False)
    .sample(frac=0.3, random_state=42)
)

train_df = eval_df.drop(test_df.index)
```

분할 결과

```
Train

8,531,170 rows

Test

3,634,030 rows
```

## 9. Content-Based 추천 방식 개선

기존 방식

```
게임 하나

↓

TF-IDF

↓

Cosine Similarity
```

↓

새로운 방식

```
게임 A

↓

Cosine Similarity

게임 B

↓

Cosine Similarity

게임 C

↓

Cosine Similarity

↓

평균 Similarity 계산

↓

Top-N 추천
```

즉,

사용자가 플레이한 모든 게임을 고려하여
평균 유사도를 기반으로 추천하도록 설계를 변경하였다.

---

## 10. TF-IDF 평균 방식과 유사도 평균 방식 비교

오늘 가장 고민했던 부분이다.

비교한 두 가지 방법

### 방법 1

```
TF-IDF 평균

↓

Cosine Similarity
```

### 방법 2

```
게임별 Cosine Similarity 계산

↓

Similarity 평균
```

현재 프로젝트에서는

방법 2가

사용자의 모든 게임 취향을 직접 반영한다는 점에서
더 적합하다고 판단하였다.

## 12. GPT와 Claude 활용 방식 정리

오늘은 프로젝트를 진행하면서

GPT와 Claude를 어떤 방식으로 활용하는 것이
학습 효율과 이해도를 모두 높일 수 있는지 고민하였다.

여러 가지 방식을 비교한 결과
다음과 같은 역할 분담을 하기로 결정하였다.

### GPT

- 프로젝트를 처음부터 직접 구현
- 개념을 하나씩 이해하며 학습
- 코드 분석
- 디버깅
- 알고리즘 원리 학습
- 프로젝트 회고 및 로드맵 관리

즉,

"내가 직접 생각하고 구현하는 과정"

을 최대한 유지하는 역할로 활용하기로 하였다.

---

### Claude

- 프로젝트 시작 전 전체 구조 검토
- 설계 누락 사항 확인
- 프로젝트 리팩토링 아이디어 제안
- 반복적인 코드 작성 보조
- 빠른 문서 작성
- 구현 속도 향상이 필요한 작업

즉,

"생산성과 설계 검토"

역할을 담당하기로 하였다.

---

### 최종 결론

프로젝트를 처음 배우는 단계에서는

GPT를 이용하여

직접 구현하고
직접 고민하는 시간을 충분히 확보한다.

반대로

이미 이해한 내용을 반복 구현하거나

대규모 코드 작성,

리팩토링,

문서 작성이 필요한 경우에는

Claude를 적극 활용하기로 결정하였다.

이를 통해

학습 효율과 이해도를 동시에 확보하는 방향으로 프로젝트를 진행하기로 하였다.

# 새롭게 알게 된 점

- 추천 시스템은 사용자 단위로 평가해야 한다.
- Train/Test는 사용자별 리뷰 기준으로 분할하는 것이 적절하다.
- 학습 데이터와 평가 데이터는 반드시 분리되어야 한다.
- 추천 입력은 실제 서비스처럼 여러 게임을 사용하는 것이 더 현실적이다.
- 여러 게임의 유사도를 평균내는 방식은 사용자의 전체 취향을 반영하기 쉽다.
- 프로젝트 초기에 평가 구조를 설계하면 이후 리팩토링 비용을 줄일 수 있다.
