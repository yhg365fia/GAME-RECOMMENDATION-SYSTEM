### 1-3. 평가 지표 이론 학습 및 구현: Precision / Recall / HitRate / NDCG

**추천 시스템 평가의 근본적인 어려움**
- 추천 시스템은 정답이 명확하지 않다. 사용자가 좋아한 아이템만 Positive로 관측되고, 추천하지 않은 아이템이 "싫어하는 것"인지 "아직 안 본 것"인지 알 수 없다.
- 그래서 Offline Evaluation에서는 Train/Test Split을 통해 미래 행동을 예측하는 방식으로 평가한다.

**Precision@K**
```
Precision@K = Hits / K
```
추천한 아이템 중 실제로 맞춘 비율. 분모가 "추천한 개수(K)"라는 점이 특징.

**Recall@K**
```
Recall@K = Hits / 실제 정답 개수
```
실제 정답 중 얼마나 찾아냈는지. 사용자의 정답이 많아질수록 Recall이 구조적으로 낮아질 수 있으며, 이는 추천 시스템에서 흔한 현상임을 이해했다.

**HitRate@K**
```
HitRate = 맞춘 유저 수 / 전체 유저 수
```
Top-K 안에 정답이 하나라도 있으면 성공(1)으로 처리. 한 개를 맞추든 다섯 개를 맞추든 동일하게 취급되어 "여러 개 맞춘 정도"는 반영하지 못하므로, Precision이나 NDCG와 함께 보완적으로 사용해야 한다는 것을 배웠다.

**NDCG@K — 왜 필요한가**
Precision/Recall/HitRate는 전부 "순서"를 고려하지 않는다는 공통된 한계가 있다. 예를 들어 정답을 1·2위에 맞춘 모델과 9·10위에 맞춘 모델은 Precision이 동일하지만, 실제로는 전자가 훨씬 좋은 추천이다. 이 차이를 평가하기 위해 NDCG를 도입했다.

```
DCG = Σ (relevance / log₂(rank + 1))
IDCG = 가장 이상적으로(정답을 전부 맨 앞에) 추천했을 때의 최고 점수
NDCG = DCG / IDCG   (0~1 사이, 1이면 완벽한 추천)
```

- `relevance`는 맞으면 1, 틀리면 0
- 순위(rank)가 뒤로 갈수록 `log₂(rank+1)`로 나눠 점수가 자연스럽게 감소
- `rank`를 0이 아닌 1부터 시작하는 이유: `log₂(1)=0`이 되어 1/0 오류가 발생하기 때문에 `rank+1`로 보정
- `ideal_hits = min(len(test_ids), top_n)`: Top10 추천에서는 정답이 아무리 많아도 최대 10개까지만 맞출 수 있으므로, IDCG 계산 시 이 상한을 적용해야 함

실제 `evaluate_user()` 함수에 위 로직을 구현하여 전체 평균 및 구간별 리포트에 `NDCG@10`을 추가로 출력하도록 완성했다.

**@K의 의미**: Precision@10, Recall@10, HitRate@10, NDCG@10에서 "@10"은 Top-10 추천 결과만으로 평가한다는 뜻이며, 추천을 100개 생성했더라도 상위 1~10위만 사용해서 지표를 계산한다.

## 2. 오늘 배운 것 (What I Learned)

### 2-1. pandas 버전 호환성 함정
`groupby().apply()`가 pandas 2.2+에서 그룹 기준 컬럼을 자동으로 배제하는 동작 변경이 있다는 것을 실전에서 겪으며 학습했다. 이런 함정을 피하려면 `for group_name, group_df in df.groupby(...)` 같은 더 명시적이고 안전한 패턴을 쓰는 것이 낫다는 것을 배웠다.

### 2-2. qcut vs cut의 근본적 차이
`qcut`은 인원(개수) 기준 균등분할, `cut`은 값 기준 분할이라는 차이를 명확히 이해했다. 데이터가 특정 구간에 몰려 있을 때 `qcut`이 경계를 지저분하게 나눌 수 있다는 것을 실제로 확인했다.

### 2-3. 코드 문법 상세 이해 (NDCG 구현 관련)
- `enumerate(recommended_ids, start=1)`: 추천 목록을 순위(1위, 2위, 3위...)와 함께 반복하기 위한 문법. `start=1`을 쓰는 이유는 `log₂(rank+1)` 공식에서 rank가 0부터 시작하면 `log₂(1)=0`이 되어 0으로 나누는 오류가 발생하기 때문.
- `sum(...)`이 반복문을 한 줄로 축약하는 문법이라는 것, 그리고 `idcg = sum(1/np.log2(rank+1) for rank in range(1, ideal_hits+1))`이 일반 for 반복문과 동일한 결과를 낸다는 것을 확인.

### 2-4. 표본 크기의 통계학적 근거
"표본이 클수록 무조건 좋다"가 아니라, 표준오차는 √n에 반비례해서 개선 효율이 점점 떨어진다(수확체감)는 것을 배웠다. 95% 신뢰수준 + ±5% 오차 기준을 만족하는 최소 표본 크기가 약 385명이라는 통계학의 표준 기준을 배웠고, 모집단이 아무리 커도(10만, 100만 명) 표본이 이미 충분히 작은 비율이면 필요한 절대 표본 수는 거의 안 바뀐다는 유한모집단 보정 개념을 이해했다.

### 2-5. NDCG가 실무/연구에서 핵심 지표로 쓰이는 이유
Precision, Recall, HitRate는 전부 "무엇을 맞췄는가"만 보고 "어디에 맞췄는가(순위)"는 반영하지 못한다는 공통적 한계를 이해했다. 추천 시스템 논문과 Kaggle 등 실전에서는 Precision/Recall/HitRate보다 NDCG를 핵심 지표로 삼는 경우가 많다는 것을 배웠다.

### 2-6. 프로젝트 목표와 디테일 사이의 균형 감각
"추천 알고리즘 체계를 비교하는 것"이 본질이고, `qcut` 경계값 미세조정이나 pandas 버그 하나하나는 부수적 비용이라는 것을 스스로 자각했다. "이 문제가 알고리즘 해석/성능 비교에 영향을 주는가?"를 기준으로, 세부 디버깅에 매몰되지 않고 우선순위를 판단하는 습관을 세웠다. 코드를 완전히 몰라도 되는 것과 반드시 이해해야 하는 것을 구분하는 기준(도구 사용법 vs 도메인 해석력)을 정리했다.

### 2-7. 실전/SOTA 벤치마크와 비교하는 눈
내 프로젝트의 낮은 recall 수치가 "잘못된 게 아니라 원래 그런 것"이라는 것을, 실제 논문 벤치마크 검색을 통해 검증하는 습관을 얻었다. "절대적인 숫자"보다 "알고리즘 간 상대 비교"가 이 프로젝트의 핵심이라는 관점을 확립했다.

**NDCG@10 = 0.0286**
Precision(0.0268)과 거의 비슷한 값으로 나왔는데, 이는 맞춘 게임들이 추천 리스트의 특정 순위(앞/뒤)에 쏠리지 않고 비교적 고르게 분포했다는 의미로 해석했다. 만약 NDCG가 Precision보다 뚜렷하게 높았다면 "맞춘 것들이 대체로 상위권에 몰려있다"는 뜻이고, 낮았다면 "맞춘 게 있어도 순위가 뒤쪽이다"는 뜻이 되므로, 두 지표를 나란히 보는 것 자체가 추천의 질을 더 입체적으로 이해하는 데 도움이 되었다.

### 구간별 경향에 대한 해석

- **26-45개 구간이 4개 지표(precision, hit_rate, ndcg) 중 3개에서 가장 높은 성능**을 보였다. 이는 게임을 적당히 많이 한 유저(입력 정보가 충분하되 정답 후보가 과도하게 퍼지지 않는 구간)에서 콘텐츠 기반 추천이 가장 안정적으로 작동한다는 가설을 세울 수 있는 근거가 되었다.
- **10-15개 구간은 모든 지표에서 가장 낮은 축**에 속한다. 입력으로 쓸 수 있는 게임(train)이 적으니, 유저의 취향을 대표하는 TF-IDF 벡터 자체가 불안정해서 추천 품질이 떨어지는 것으로 해석했다. 이는 협업 필터링에서 흔히 말하는 콜드스타트(cold-start) 문제와 유사한 양상이다.
- **46-78개 구간은 recall만 유독 낮다.** 이는 "추천을 못해서"가 아니라 "정답 후보 자체가 너무 많아서(구조적 한계)"로 해석하는 것이 타당하며, 이 구간만 놓고 "이 모델이 안 좋다"고 판단하면 안 된다는 점을 유의했다.

### 종합 판단: 왜 전반적으로 점수가 낮게 나오는가

추천 시스템 평가는 본질적으로 어려운 문제라는 것을 다시 확인했다. 그 이유는:
1. **정답 자체가 불완전하다** — 유저가 플레이하지 않은 게임이 "싫어서"인지 "아직 몰라서"인지 데이터만으로는 구분할 수 없다. 그런데 evaluation은 test set 이외의 모든 추천을 사실상 "틀림"으로 채점하므로, 실제로는 유저가 좋아했을 수도 있는 게임을 추천해도 점수에 반영되지 않는다.
2. **카탈로그가 크고 후보가 극단적으로 많다** — 수만 개 게임 중 Top-10만 맞혀야 하니, 우연히 맞을 확률 자체가 매우 낮다.
3. **콘텐츠 기반 모델의 구조적 한계** — 장르/태그 텍스트 유사도만으로는 유저 개개인의 취향 패턴(협업 신호)을 반영하지 못한다.

따라서 지금 수치(Precision/Recall/NDCG 0.02~0.04대)는 "모델이 잘못됐다"는 신호가 아니라, **콘텐츠 기반 방식의 구조적 한계 + 추천 평가 자체의 근본적 어려움**이 함께 반영된 결과로 해석했다. 이 낮은 점수 자체가 나쁜 게 아니라, **다음 단계(협업 필터링, 하이브리드)와 비교할 기준선(baseline)이 마련되었다는 것**에 의미가 있다.
